SkillEvolve-CR · 三轮自优化执行链路

从你在页面点下「多轮优化 · 3 轮」那一刻开始，后台真实发生的全部步骤。链路对 3 轮通用：每轮结构完全相同，轮次间仅 SKILL 版本可能不同。
触发/编排 ① 检视生成（headless） ② 评分（headless） ③ 指标汇总（Python） ④ SKILL 优化（headless） 闭环护栏 产物落盘

建 run 目录runs/<run_id>/{skills, changelogs}
评测集快照dataset_snapshot.jsonl · 之后改评测集不影响本 run

解析起始 SKILLmain / baseline / weak → 写入 skills/skill_v1.md

2 · Round N 循环体 N = 1, 2, 3 · 每轮每案例每阶段都是独立 claude -p 进程
使用技能 vN轮次隔离：本轮所有阶段在 round_0N/ 各自的子工作区进行，SKILL 以快照装入 .claude/skills/
① 检视生成 · code-review每案例独立 claude -p（并发 N）→ 产出检视意见
findings/case-x.json
trace：每案例全程 stream-json + session 费用/时长
② 评分 · score-review每案例独立 claude -p：逐条判定 TP / FP
未被任何意见命中的标准答案 → FN
Python 只做确定性汇总，不掺模型判断
③ 指标汇总P = TP/(TP+FP) · R = TP/(TP+FN) · F1
写 metrics.json（含每案例明细）
更新「历史最佳」追踪（F1 不降则本轮技能成为新基准）
④ 是否执行 SKILL 优化？（按序判定，命中即止）
护栏 A · 满分跳过FP=0 且 FN=0 且链路无告警 → 跳过优化，下一轮沿用 vN（为改而改只会引入回归）
护栏 B · 末轮默认跳过已是最后一轮且 optimize_last_round=false → 不优化，闭环结束
执行优化 · optimize-review输入：错例包（FP/FN 案例含 diff）+ trace 链路诊断 + 上一轮 changelog → 单次 claude -p 产出新 SKILL + changelog
校验失败frontmatter / name 不变 / 非空 / 与上一版不同 / JSON 契约字段 缺一不可 → 校验不过，下一轮沿用 vN
回退护栏新版本在下一轮实测 F1 < 历史最佳 → 优化产物丢弃，自动回退到历史最佳版本继续
采纳 → vN+1写 skills/skill_vN+1.md + changelogs/changelog_vN_to_vN+1.json → Round N+1 使用新版本
Round N+1 以（可能已升级的）技能重复上述循环体，直至 N=3
